# Bottleneck Analysis Dashboard

## Purpose
The Bottleneck Analysis dashboard (Module 6.4) provides a detailed visual breakdown of system constraints and the effectiveness of tested interventions. It is designed to quickly identify the primary "active bottleneck" restricting system throughput, separating superficial queues from genuine operational limits.

## Data Source & Integrity
The dashboard reads solely from the pre-aggregated canonical analytical metrics generated in Modules 5.7 and 6.1:
- `dashboard_bottleneck_summary.csv`: Contains normalized bottleneck scores and roles (Active vs Unconstrained).
- `dashboard_intervention_ranking.csv`: Contains the prioritized ranking of scenarios based on flow-time ROI.
- `dashboard_stage_metrics.csv`: Used for baseline comparative queue and utilization plotting.

No synthetic events are regenerated, maintaining deterministic integrity with the foundational model configuration.

## Key Visualizations & Analytics
- **Baseline Bottleneck Identification**: Clearly pinpoints the `DISPATCH` stage as the highest bottleneck based on the normalized scoring of its utilization (31.15%) and continuous active queueing behavior.
- **Stage Utilization Chart**: A clear breakdown of worker utilization, highlighting the active bottleneck in red versus boundary constraints in orange.
- **Queue Distributons (Mean & P95)**: Bar charts plotting expected queue lengths vs peak 95th-percentile queuing behaviors.
- **Waiting Time Contribution**: A pie chart detailing how waiting time is distributed across stages (where PROCESSING wait time largely stems from overnight queue rollovers).
- **Intervention Ranking Chart**: A grouped visualization detailing how specific process changes (Extended Shift, Worker Capacity adjustments) compare regarding systemic flow time improvement percentage.

## Interpretations & Conclusions
The visualization formally validates the conclusions from Module 5.7: adding capacity to non-bottleneck operations (such as `PACKING` or `PICKING`) yields negligible systemic improvement. True flow-time ROI is only generated by either attacking the active bottleneck (`DISPATCH`) or expanding the process boundary (Extended Shift).
